Cargo feature unification only adds declared requested features and their implications. Auditing *every* original lock direct serde_json consumer, including inactive/dev/build/platform possibilities, is a conservative superset of the actual wheel dependency subgraph. Omitting inactive consumers cannot introduce a feature absent from that superset. Any feature forwarded to serde_json by another crate must pass through a direct serde_json consumer's dependency declaration or feature mapping; these complete entries/manifests were examined, including renamed dependency metadata. serde_json's own feature closure was checked too. Therefore the original declared graph does not activate the three options. A helper's graph was not substituted for the original graph, and no finite corpus is used as a universal proof.

The remaining link is a **trust-based inference**: the authenticated official release used the advertised original source, lock and configuration in the ordinary way. The signature establishes who made the source/build claim and which artifact it covers, not the truth of every hidden compiler input. We accept that normal upstream build trust for this narrowly scoped compatibility premise because it satisfies the existing source/build standard; this is not a claim that hostile/modified runner state, floating-action changes, global flags or unrecorded lock updates have been disproved. Lack of --locked is a real reproducibility limit. We do not promote the static graph into a captured original invocation.

Original run logs remain unavailable through the recorded access path (403), and artifacts API reports zero. Those facts do not prove no logs exist or that hidden build settings were inspected.
